# 映像処理

## 処理経路

動画フレームをWebGPUへ入力し、カラーレンジ変換とAnime4Kパイプラインを適用してCanvasへ表示する。
直接動画転送は既知の画素と比較して妥当性を確認できた場合だけ使用する。
検証不能または不一致の場合は2D CanvasとImageBitmapを使う互換経路へ戻す。

## ライフサイクル

- WebGPU Deviceは同一タブのcontent script内で再利用する。
- Device lost時はキャッシュを破棄し、安全に再取得する。
- Renderer停止時はDeviceを破棄せず、Renderer固有のTexture、Buffer、Canvas状態だけを解放する。
- ページ破棄時に共有Deviceを破棄する。
- 動画切替時は旧コールバックと統計を無効化し、前動画のフレーム情報を残さない。

## 時間同期とサイズ

- GPUへ投入中のRendererでは次フレームを積まず、処理可能になった時点の最新フレームを扱う。
- 制御単位はタブ内のRendererとし、別タブの再生を止めない。
- 表示サイズの変化が実レンダー寸法の0.5%未満かつ4px未満なら再構築しない。
- フルスクリーンなど有意なサイズ変更後は、安定した表示寸法で再構築する。
- 最大テクスチャ寸法とプロジェクト上限を超えない。
